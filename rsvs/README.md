# 机器人技能可视化演示交互系统

本项目是一套面向 **Unitree Go2 四足机器人**的仿真演示与交互系统，基于 Genesis、PyTorch、Viser、Legged Gym 和 RSL-RL 构建。

系统加载已经训练完成的强化学习策略，在 Genesis 物理仿真环境中实现机器人高动态技能、自主导航和基础运动控制，并对机器人姿态、运动状态、传感器数据及规划结果进行三维可视化。

## 🤖 核心功能

### 高动态技能演示

系统内置多个针对特定动作训练的策略模型，可以控制 Go2 完成：

- 前脚倒立；
- 后腿站立循环；
- 单次后空翻；
- 连续后空翻；
- 向前弹跳。

技能执行过程不是预先录制的固定动画。系统会持续读取机器人的机身姿态、角速度、关节位置和关节速度，由策略网络实时计算关节动作。

技能模块还实现了动作交接、落地判断、站稳恢复、急停、复位、重放、执行进度显示和场景截图等功能。

### 自主导航

自主导航模块将环境感知、路径规划和强化学习运动控制组合为一条完整链路：

```text
LiDAR 扫描
    ↓
占据栅格建图
    ↓
障碍物膨胀与可通行区域判断
    ↓
A* 路径规划与动态重新规划
    ↓
局部目标点和速度指令
    ↓
强化学习行走策略
```

导航模块支持 360° LiDAR 扫描、占据栅格更新、A* 全局规划、动态重新规划、近距离障碍排斥、终点约束与到达判断，以及路径、点云和占据地图显示。

系统提供通道与障碍柱、小围栏和开阔障碍场等多种导航环境。LiDAR 不可用时，可以回退到静态障碍地图。

### 运动控制

项目包含训练完成的 `go2_wtw` 行走策略，可以接收高层速度和行为指令，实现：

- 前进与后退；
- 左右横移；
- 左右偏航；
- 停止与站立复位；
- 运动指令幅度调节；
- 步态周期和机身高度调节；
- 相机跟随与自由视角切换。

系统支持四种基础步态：

| 步态 | 策略名称 | 运动特点 |
|---|---|---|
| 对角小跑 | `trot` | 对角腿同步运动 |
| 前后跳跃 | `bound` | 前腿和后腿分组跳跃 |
| 对侧跑步 | `pace` | 同侧腿交替运动 |
| 四足齐跳 | `pronk` | 四条腿同步跳跃 |

## 🧠 强化学习的作用

强化学习策略是系统中的底层运动控制器，负责将高层任务指令转换为 Go2 的 12 个关节动作。

```text
速度指令 / 技能指令
          ↓
机器人状态与历史观测
          ↓
预训练强化学习策略
          ↓
关节目标位置或控制力矩
          ↓
Genesis 物理仿真
```

项目中的强化学习主要承担两类任务：

1. **通用行走控制**：根据纵向速度、横向速度、偏航速度和步态参数控制四条腿协调运动。
2. **专用技能控制**：使用独立策略完成倒立、站立、后空翻和弹跳等高动态动作。

自主导航不是完全由强化学习实现。LiDAR 负责环境感知，A* 负责路径规划，强化学习策略负责让机器人按照规划产生的速度方向稳定运动。

系统正常运行时直接加载已有模型进行推理，不会重新训练智能体。

## 🏗️ 系统组成

| 模块 | 作用 |
|---|---|
| `skills` | 高动态技能加载、执行和状态管理 |
| `nav` | LiDAR、占据栅格、A* 规划和导航控制 |
| `play` | Go2 行走策略、步态切换和运动控制 |
| `common` | 三维显示、机器人网格、相机、状态栏和快捷键 |
| `weights` | 行走、导航及高动态技能的预训练权重 |
| `assets` | Go2 技能仿真模型和场景资源 |
| `resources` | Go2 机器人描述、URDF 和网格资源 |
| `legged_gym` | 四足机器人任务环境和仿真接口 |
| `rsl_rl` | 策略网络、PPO 算法、运行器和数据存储 |
| `vendor` | 技能组合与导航链路所需的内置脚本 |

## 🔧 技术特点

- 使用 Genesis 完成刚体动力学和关节控制仿真；
- 使用 PyTorch 加载并执行强化学习策略；
- 使用 Viser 同步显示机器人连杆姿态和场景信息；
- 支持 GPU 和 CPU 两种计算后端；
- 模型、权重和机器人资源集中存放在项目目录中；
- 技能、导航和运动控制模块相互独立，可分别运行和扩展；
- 保留 Legged Gym 与 RSL-RL 的核心结构，便于后续研究和策略调整。

## ⚠️ 使用范围

当前项目主要用于机器人仿真研究、算法验证和技能效果演示，实际控制对象是 Genesis 环境中的虚拟 Go2。

项目尚未直接集成 Unitree 实机 SDK、ROS 通信或真实电机控制接口。如需部署到实体机器人，还需要完成通信接口、安全限制、急停保护、状态估计和 Sim-to-Real 适配。
