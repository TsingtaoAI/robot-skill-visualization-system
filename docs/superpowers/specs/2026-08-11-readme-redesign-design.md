# GitHub README 重构设计

日期：2026-08-11

## 目标

将仓库根目录的 `README.md` 重写为纯中文、文字优先的 GitHub 项目首页，让访问者能够快速理解项目用途、核心功能、运行方式和当前限制。

## 视觉原则

- 不使用大幅横幅、复杂卡片或装饰性背景图。
- 标题和正文保持标准 Markdown 排版。
- 仅在一级功能章节使用少量 Emoji，例如 `🤖`、`✨`、`🧠`、`🚀`、`⌨️`、`📁`、`⚠️`、`🙏`。
- 顶部最多放置四个小型技术徽章，分别表示 Python、Genesis、PyTorch 和 Unitree Go2。
- GIF 只作为技能预览辅助，不替代文字说明，也不占据过多页面空间。

## 内容结构

1. 项目名称、中文简介和技术徽章。
2. 项目简介：说明系统面向 Unitree Go2，使用 Genesis、PyTorch、Viser 和预训练强化学习策略。
3. 核心功能：技能演示、自主导航、运动遥控和统一 Web 门户。
4. 强化学习策略：解释高层指令到 12 个关节动作的控制关系，并区分 A* 路径规划与强化学习运动控制。
5. 系统架构：使用简洁文本流程图描述浏览器、导航、策略网络和 Genesis 仿真的数据流。
6. 快速开始：给出环境要求、依赖安装、门户及三个模块的启动命令。
7. 操作说明：列出默认端口、主要快捷键和四种步态。
8. 项目结构：解释仓库内 `rsvs/` 下的核心目录。
9. 注意事项：明确当前版本是仿真系统，不直接连接实体机器人。
10. 致谢与许可：说明第三方代码、机器人模型和策略权重需遵守各自许可证。

## 准确性要求

- 不宣称当前代码已经支持实体机器人部署。
- 不将 A* 路径规划描述为强化学习算法。
- 不声称正常启动过程会重新训练策略。
- 明确当前仓库目录使用 `rsvs`，而源码内部仍引用 `newtest` 包名，独立克隆后的启动兼容性尚待统一。
- 所有端口、技能名称、步态名称和启动模块必须与现有源码一致。

## 验收标准

- README 为纯中文，只有技术名词和命令保留英文。
- GitHub Markdown 标题、表格和代码块闭合完整。
- 首屏能够看出项目用途和三项核心能力。
- 安装与启动命令可以复制，路径层级与当前仓库结构一致。
- 页面没有无效的本地绝对路径图片。
- 内容明确区分已实现功能、底层保留能力和当前限制。
